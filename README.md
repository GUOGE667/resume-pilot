# ResumePilot · 简历编辑器

[在线站点](https://resumepilot-ai-career.guolinghao6.chatgpt.site/) · [配套面试训练 EchoHire](https://github.com/GUOGE667/echohire-ai-interview)

ResumePilot 帮助学生整理个人经历，对照目标岗位修改简历，并将简历带入 EchoHire 做模拟面试。面试反馈可以带回简历编辑页形成修改线索。公开站点无需 ChatGPT 登录。

## 已实现

- 结构化编辑个人信息、教育、经历、项目和技能；教育、实习和项目均可添加多条，并同步进入两套模板的实时 A4 预览。
- 上传头像，并随简历预览导出 PDF；推荐在“文字版 PDF”的打印窗口选择“保存为 PDF”，保留可复制、可搜索的文字。原图片版由浏览器端 `html2canvas` 和 `jsPDF` 生成，分页优先选在章节、条目和文本行的边界。保存后可点击预览区“检查 PDF”，由浏览器本地提取文字并核对页数、中文与当前简历的关键字段；此检查不能代替人工版式检查或保证 ATS 结果。
- 可导入已有的文字版 PDF 简历。浏览器本地提取文字并保守识别姓名、联系方式、简介、教育、工作和项目等字段；先展示可编辑预览，由用户确认后才保存为新的简历版本，原版本不被覆盖。扫描件和复杂多栏版式可能无法完整识别，需人工核对。
- 浏览器本地自动保存与手动保存；最多五份具名简历版本，可复制当前版本并按岗位分别修改、切换和删除；版本对比逐字段展示文字变化，分别检查各自 JD 的关键词提及情况；支持当前版本与全部版本的 JSON 备份下载和确认后导入。虚构示例标记及一键清空；岗位关键词逐条对照 JD 与简历原文，标明未提及项；规则处理常见别名、否定要求与重复提及；免费内容检查引用原句指出行动、方法或结果的缺口。
- 点击按钮以 URL 片段把简历正文和岗位描述交给 EchoHire；EchoHire 反馈也可用 URL 片段返回。头像、联系方式不在该正向交接的简历正文中。
- EchoHire 当前免费模式会从导入的具体项目或实习描述生成最多两道显示原文依据的定制题；无法提取可靠描述时回退到岗位与职位 JD 题目。

## 数据与边界

- 各版本每次修改后立即保存在**当前浏览器 localStorage**，仍可手动保存；换浏览器或清理本地数据后不会自动恢复。若浏览器拒绝存储，页面会显示保存失败。首次打开新版时，原有单份草稿会成为“主简历”。
- 备份文件由浏览器本地生成、读取，不上传到站点；文件可能包含姓名、联系方式和经历，请自行保管。可单独备份当前版本，也可备份全部版本。导入前会预览备份范围和时间，并要求再次确认：单份备份覆盖当前版本，全部版本备份覆盖当前浏览器的所有版本。可用备份文件在另一设备手动恢复。
- 旧版单条经历的浏览器草稿和 v1 JSON 备份会自动转为多条结构；新下载的备份是 v2 格式。每类经历最多 20 条。
- “检查当前内容”只在当前浏览器内运行，不向站点接口发送段落或职位 JD，也不调用付费模型。规则只提供有原文依据的修改线索，不会生成或自动应用未经证实的履历内容。仓库保留的 `/api/optimize` 可选接口不在页面中调用；只有所有者以后显式开启付费开关并主动调用该接口，才可能使用 API 额度。
- “导入已有 PDF”只在当前浏览器读取文件，解析预览未确认前不写入草稿；确认后会另建一个本地版本。解析不使用 OCR，也不会自动填补缺失事实。请人工核对各字段和原文；多栏 PDF 的读取顺序可能不准确。
- “检查 PDF”直接在当前浏览器解析用户选择的 PDF，不上传、不持久保存该文件；它只检查文字提取和部分关键字段，不能验证视觉排版或招聘系统的最终解析。
- 岗位关键词对照在浏览器内运行，只检查可识别词语的文字提及情况；常见否定、转折和技术别名有回归测试，但仍可能误判或漏判。它不能验证实际能力、判断是否胜任，也不表示录用概率。
- 版本对比在当前浏览器内只读运行，不会改变任何简历。各版本关键词数字依据各自的 JD 生成；JD 不同时不能用数字直接判断哪个版本更适合岗位。经历条目先按完全相同内容、再按学校／公司／项目名称对齐；更名可能显示为移除旧条目并新增新条目。
- 即使服务端配置了 OpenAI API Key，页面的本地检查也不会产生付费请求。仅保留的可选接口在所有者显式配置 `RESUMEPILOT_ALLOW_PAID_API=true` 且直接请求该接口时可能调用模型；公开站点开启该开关后，访客也可能触发费用。模型调用设置 `store: false`。
- URL 片段交接由用户点击发起；简历内容可能保留在本机浏览器历史等环境中，不应用于敏感资料的安全传输。
- 站点与 EchoHire 没有统一身份、共享数据库或自主执行的跨产品 Agent。

## 本地运行

Node.js ≥ 22.13、pnpm 11：

```powershell
pnpm install
Copy-Item .env.example .env.local
pnpm dev
```

本地运行默认无需 API Key。若所有者将来决定启用付费模型，再同时配置 `RESUMEPILOT_ALLOW_PAID_API=true` 与自己的 `OPENAI_API_KEY`；不要将真实密钥提交到 Git。运行 `npm run lint`、`npm run typecheck`、`npm test` 和 `npm run build` 检查源码。跨站闭环的人工验收步骤见 [EchoHire 作品集说明](https://github.com/GUOGE667/echohire-ai-interview/blob/main/docs/PORTFOLIO.md)。

## 质量检查

运行 `npm run lint`、`npm run typecheck`、`npm test` 和 `npm run build` 可检查静态规则、TypeScript 类型、草稿备份与岗位对照等逻辑，以及生产构建。GitHub Actions 的 `CI` 工作流会在推送到 `main` 或提交 PR 时运行同一组检查，不需要 OpenAI API Key。

## 说明

默认简历是虚构示例，不是作者的真实履历。页面和含示例内容的 PDF 预览会显示提示，可一键清空完整示例。项目用于学习和作品集展示。
